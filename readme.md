1. 这个项目是一个路径路由项目。go run cmd/view/main.go
2. 我的目标是把它实现可以根据路径的延迟来选择最优的路径，最终在网络节点之间根据网络延迟来选择最优的路径。
如果节点之间的underlay是TCP协议的话，由于TCP会重传，所以从overlay的角度上看，它没有丢包的，所以延迟成为了这个隧道唯一的指标，可以影响这条隧道的cost值,当cost值的变化超过10%的时候，可以触发路由计算；
如果underlay是udp协议的话，或者相关的基于报文传输的协议，那么隧道内是可以感知到丢包的，所以延迟和丢包成为影响cost的两个因素

网络节点之间的cost越小， 路径越优。
3. 网络节点之间的延迟和实时流量，由节点上报到数据库里(比如influxdb等其他可快速记录节点延迟的时间序列数据库), 然后程序从数据库里读取节点之间最近的延迟, 并根据延迟来计算出节点之间的cost, 如果节点之间的cost变化超过某个阈值，就重新计算最优路径，这样数据就按最优路径上流转。

4. TODO: 但这样有个问题，某个两个节点之间的最优路径发送切换,切到新的路径后，由于新路径有了数据流量，跑满了带宽，延迟会变大，而旧路径延迟因为没有数据，所以延迟会变小，重新计算最优路径后又会切换回旧路径，旧路径也因为有了流量导致延迟变大，从而又发生路径切换。这样来回反复切换，最终没有让数据永远是高延迟的。

         /--->B ---->
       /             \        /--->E
A -- \               /--->D /
       \---->C ---> /       \----->F

比如这种拓扑，如果C 和D， B和D之间的带宽不大，瓶颈出现在它们之间的延迟上。A 到E、 A 到F的流量应该部分走B 和部分走C， 这样就不会让B和D之间的延迟过大， 也不会让C和D之间的延迟过大。

要做到这种效果，必须记录节点之间多大的流量会延迟变大(最好是如果流量没有到设置带宽)，这样才能把流量分配到不同的路径上。

比如, A 的带宽100M, B 的带宽50M, C 的带宽30M, D 的带宽100M, E 的带宽100M, F 的带宽100M。 那么A-B的带宽就是50M，但是A 还可以发送数据到C,因为A的带宽还没满，还能给C发送30M的数据。

5. 节点如果用一个网口来连接其他节点， 那么这个节点口的延迟和流量，就只能根据这个网口来计算。
