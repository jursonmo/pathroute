## PathRoute

这是一个根据有向边状态和实时指标计算最优路径的 Go 项目。当前首版已经支持：节点或模拟器上报 TCP/UDP 边指标、ClickHouse 原始时序存储、MySQL 动态 cost 快照、revision 一致的 Floyd 路由重算，以及用于配置和观察整条链路的测试页面。

快速启动静态模式：

```bash
go run ./cmd/view
```

动态模式需要 MySQL 与 ClickHouse，完整配置、数据库初始化、API 和验证命令见 [`cmd/view/README.md`](cmd/view/README.md)。默认每 2 秒生成/聚合指标，10 秒平滑窗口，30 秒过期；TCP cost 使用延迟，UDP cost 使用 `延迟 + 丢包率 × 1000`。指标过期不会改变边的 `status`：`status != 1` 才表示边不可用，可用但指标全部过期的边以 cost 1000 继续参与路由。

## 设计背景与后续方向

我的目标是把它实现可以根据路径的延迟来选择最优的路径，最终在网络节点之间根据网络延迟来选择最优的路径。
如果节点之间的underlay是TCP协议的话，由于TCP会重传，所以从overlay的角度上看，它没有丢包的，所以延迟成为了这个隧道唯一的指标，可以影响这条隧道的cost值,当cost值的变化超过10%的时候，可以触发路由计算；
如果underlay是udp协议的话，或者相关的基于报文传输的协议，那么隧道内是可以感知到丢包的，所以延迟和丢包成为影响cost的两个因素

网络节点之间的cost越小， 路径越优。
网络节点之间的延迟和实时流量，由节点上报到时序数据库，然后程序读取最近指标并换算 cost；当变化满足阈值和连续确认条件时，重新计算最优路径。

TODO：当前首版只做单路径选择，不解决容量约束和多路径分流。某两个节点之间的最优路径发生切换后，新路径可能因流量增加而延迟变大，旧路径因空闲而延迟变小，进而形成反复切换。

         /--->B ---->
       /             \        /--->E
A -- \               /--->D /
       \---->C ---> /       \----->F

比如这种拓扑，如果C 和D， B和D之间的带宽不大，瓶颈出现在它们之间的延迟上。A 到E、 A 到F的流量应该部分走B 和部分走C， 这样就不会让B和D之间的延迟过大， 也不会让C和D之间的延迟过大。

要做到这种效果，必须记录节点之间多大的流量会延迟变大(最好是如果流量没有到设置带宽)，这样才能把流量分配到不同的路径上。

比如, A 的带宽100M, B 的带宽50M, C 的带宽30M, D 的带宽100M, E 的带宽100M, F 的带宽100M。 那么A-B的带宽就是50M，但是A 还可以发送数据到C,因为A的带宽还没满，还能给C发送30M的数据。

节点如果用一个网口来连接其他节点，那么这个节点口的延迟和流量只能根据这个网口来计算。
